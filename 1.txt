==================================================
0. 本轮任务重新明确
==================================================

我们现在不是继续做 3 条 demo。

目标是正式构建：

Real-World Evidence-Family Time-Series QA Benchmark v1

核心科学问题：

1. 面对真实世界时序，
   language model 到底能够读取哪些 temporal information？

2. 面对同一份时序、不同自然语言问题，
   模型能否选择并使用正确的 temporal evidence？

3. 当与当前问题相关的证据发生变化时，
   模型能否正确更新答案？

4. 当只有无关证据发生变化时，
   模型能否正确保持答案？

5. language-model pretraining
   究竟使哪些能力变得更可读 / 更容易被使用？

Benchmark 不是为了做 leaderboard SOTA。

它是一个：

controlled diagnostic benchmark

用于分析：

temporal information accessibility
+
question-conditioned evidence use
+
native QA behavior
+
pretraining attribution

==================================================
1. Benchmark 必须拆成两个 Track
==================================================

这是正式设计，不能把两类数据混着报告。

--------------------------------------------------
Track R：Observed Real QA
--------------------------------------------------

数据必须来自真实采集记录。

不能修改原始时序。

允许：

- 截取合法时间窗口
- 保留/选择通道
- 保留原始 timestamp
- 合理的、记录清楚的单位转换
- 为显示精度做事先固定的舍入

不允许为了制造答案：

- 插入异常
- 移动事件
- 修改峰值
- 拼接假的 regime
- 人为改变周期
- 重新排列数值

这一 Track 回答：

在未经人工改变的真实时序上，
LLM 能否回答问题？

--------------------------------------------------
Track I：Evidence Intervention QA
--------------------------------------------------

底层仍然必须来自真实时序记录。

但是允许进行受控 intervention：

x -> T(x)

目的不是伪装成真实采集数据，
而是建立可以验证因果式行为关系的测试：

q_target：
gold 必须变化

q_control：
gold 必须保持

所有 intervention 样本必须明确标记：

derived_from_real = true
intervention_type = ...
source_record_id = ...

论文和数据卡中不能将 Track I
称为未经修改的 real-world observation。

==================================================
5. Benchmark QA taxonomy
==================================================

不要按数据集来定义任务。

跨 domain 使用统一能力 taxonomy。

正式 v1 使用以下六类：

A. Global Structure QA
B. Numeric Reading QA
C. Temporal Localization QA
D. Temporal Relation QA
E. Multi-evidence Composition QA
F. Conditional Reasoning QA

--------------------------------
A. Global Structure
--------------------------------

例如：

- 指定区间总体上升/下降/近似稳定？
- 主要重复间隔是多少？
- 哪一段波动更强？

只允许使用从可见数据可以稳定计算的定义。

--------------------------------
B. Numeric Reading
--------------------------------

例如：

- 指定区间均值是多少？
- 两区间均值差是多少？
- 最大值/最小值是多少？
- 两通道中哪一个平均值更高？

这一类必须保留。

因为：

current-value/statistical numerical extraction

与：

future forecasting

不是一回事。

--------------------------------
C. Temporal Localization
--------------------------------

例如：

- 最大值在哪个时间区间？
- 最大局部偏离在哪个区间？
- 已有权威事件标签时，事件在哪？
- 变化点在哪？

不能把隐藏注入位置直接当成真实世界 gold。

--------------------------------
D. Temporal Relation
--------------------------------

例如：

- A/B 哪一条重复间隔更长？
- 两通道哪个先变化？
- 哪个区间波动更大？
- 哪个事件先发生？

--------------------------------
E. Multi-evidence Composition
--------------------------------

要求同时读取两个及以上事实。

例如：

“哪项描述同时正确概括
该区间的重复结构和局部事件位置？”

不能只预测一个 dataset family label。

--------------------------------
F. Conditional Reasoning
--------------------------------

问题明确给出条件：

- 先选择均值更高的区间，
  再回答该区间峰值位置；

- 在变化更明显的通道中，
  判断哪个事件先发生；

- 在指定阈值条件成立的窗口中，
  找出波动最大的区段。

这里才是真正的：

question-conditioned multi-step temporal QA。

==================================================
6. 同一真实时序必须支持多个问题
==================================================

这是硬约束。

不能：

一条时序只对应一个固定 task label。

每个正式 family 必须围绕同一份 evidence
产生多个不同问题。

至少覆盖 3 种 ability type。

至少包含：

- 一个 target question
- 一个 control question

并且至少一部分 family 中：

相同 answer type
+
不同 queried region / channel / operator

例如：

同一 ECG / sensor window：

Q1：
前半段峰值在哪个四分位？

Q2：
后半段峰值在哪个四分位？

Q3：
前后哪段均值更高？

Q4：
整体重复间隔是多少？

同一份 evidence，
question 真正决定模型应该读什么。

==================================================
7. Evidence-family 四格正式定义
==================================================

每个 intervention family：

t0 = x + q_target -> a
c0 = x + q_control -> b
t1 = T(x) + q_target -> a'
c1 = T(x) + q_control -> b'

必须满足：

target：
acceptable answer sets disjoint

G_t0 ∩ G_t1 = empty

不能只检查：

a != a'

尤其连续数值题必须保证：

|a' - a| >
tolerance(a) + tolerance(a')

Control：

semantic gold 完全保持：

G_c0 = G_c1

所有判断都针对：

模型最终实际看到的
serialized / rounded / resampled input

重新计算。

不能只根据修改前原始高精度数组判断。

==================================================
8. Intervention 设计原则
==================================================

Intervention 必须改变一个明确、可观测事实。

优先使用局部和最小修改。

例如：

- 移动一个明确局部事件；
- 对指定区间添加固定 offset；
- 对一个通道做局部 amplitude change；
- 交换两个已定义区间；
- 改变局部事件顺序；
- 修改一个区间的 scale。

每个 intervention 必须运行：

target gold recomputation
control gold recomputation

只有同时满足：

target changes
control invariant

才进入正式 manifest。

如果变换同时改变了 control 所问事实：

丢弃这个 family，
不是硬保留旧 gold。

Observed Real QA 本身独立报告。

它的核心测试是：

same evidence

Intervention 是额外 diagnostic track，

==================================================
11. Answer choice 构造
==================================================

重要：

t0/t1：

question 文本原则上相同；
candidate semantic set 相同；
candidate order 相同。

c0/c1 同理。

只有 evidence 变化。

先建立 semantic option set，
再进行 position assignment。

不能根据当前 gold
重新生成一套更“适合”它的选项。

==================================================
12. Answer position balance
==================================================

不能简单写：

hash -> permutation

然后假设已经平衡。

实现：

stable hash
+
constrained balanced assignment。

在：

domain × task_type × split

内：

binary：
A/B 尽量 50/50

4-choice：
A/B/C/D 尽量 25/25/25/25

同时分别审计：

t0
c0
t1
c1

的位置分布。

保存固定：

option_manifest.jsonl

正式测试后不得修改。

禁止使用 Python 内置 hash()
作为跨进程稳定 seed。

使用 SHA-256 / blake2 等稳定哈希。

==================================================
14. Benchmark 主指标
==================================================

沿用：

Four-cell Joint Success (FCJS)

FCJS =
mean_i[
 C_t0 *
 C_c0 *
 C_t1 *
 C_c1
]

四格全部答对才算成功。

但正式描述只能写成：

joint success on the four-cell behavioral test

不要写成：

pure understanding score
或
causal understanding score。

==================================================
15. 必须同时报告
==================================================

FCJS 不能单独出现。

必须同时报告：

Acc_t0
Acc_c0
Acc_t1
Acc_c1

TUS =
mean(C_t0 * C_t1)

CIS =
mean(C_c0 * C_c1)

QSJA =
1/(2N) *
sum[
 C_t0*C_c0
 +
 C_t1*C_c1
]

VOR

以及：

TUS | t0 correct
CIS | c0 correct

prediction change rate
spurious control change rate

最后两项只作行为诊断，
不能作为成功率。

==================================================
16. Question-only 的解释必须锁死
==================================================

Question-only 继续做。

但是：

由于 target before/after 问题文本相同
而正确答案不同，

deterministic question-only model
理论上无法同时满足 t0 与 t1。

因此：

禁止使用：

FCJS_full > FCJS_question-only

作为“模型理解 temporal evidence”的主要证据。

Question-only 主要报告：

- cell accuracy
- answer distribution
- position bias
- language/template prior

Evidence use
主要由：

correct update
+
correct invariance
+
question switching

综合判断。
